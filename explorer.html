Two developers, never waiting on each other

The split is arranged so that no task ever depends on a task the other developer is doing in the same week. Cross-arrows always point backwards in time.

Dev A

Engine · correctness · performance

134 hours · no frontend, no infrastructure

Dev B

Platform & product

234 hours · carries 64% of the work

1 · One joint session, day one

Both write the event schema, the REST paths and the WebSocket message shapes together. Half a day, and it is the only time they must work in lockstep.

2 · Stub first, integrate later

Three stubs, about an hour each: a stub engine, a mock WebSocket server, and a handful of sample history files. Each lets one developer start before the other has finished.

3 · Swap the stub at week's end

Short joint sessions where a stub is replaced by the real thing. End of week 2, end of week 5, start of week 7.

The rule to check against

No task may depend on a task assigned to the other developer in the same week.
